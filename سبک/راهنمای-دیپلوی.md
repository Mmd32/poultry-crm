# راهنمای دیپلوی CRM مرغداری

Netlify فقط استاتیک/فرانت‌اند رو میزبانی می‌کنه، نه Django + Postgres + Redis + Celery. پس فرانت‌اند روی **Netlify** و بک‌اند روی **Railway** دیپلوی می‌شه. کدها از قبل برای این مسیر آماده شدن (whitenoise، gunicorn، پشتیبانی از `DATABASE_URL`، `netlify.toml`، و غیره).

## بخش ۱: بک‌اند روی Railway

1. یک ریپازیتوری گیت‌هاب بسازید و کل پروژه (backend + frontend) رو push کنید. اگه `db.sqlite3` توی گیت هست، حذفش کنید (`git rm --cached backend/db.sqlite3`) چون در production از Postgres استفاده می‌شه.
2. به [railway.app](https://railway.app) برید، با گیت‌هاب لاگین کنید و **New Project → Deploy from GitHub repo** رو انتخاب کنید و ریپو رو بزنید.
3. Railway چون هم `backend` و هم `frontend` توی ریپو هست، باید بهش بگید Root Directory سرویس بک‌اند `backend` هست: در تنظیمات سرویس (Settings → Root Directory) بنویسید `backend`.
4. توی همون پروژه، **New → Database → Add PostgreSQL** بزنید. Railway خودش متغیر `DATABASE_URL` رو می‌سازه و به سرویس بک‌اند وصل می‌کنه (Variables → Reference).
5. همینطور **New → Database → Add Redis** بزنید (برای Celery). متغیر `REDIS_URL` رو مشابه بالا به سرویس بک‌اند وصل کنید.
6. روی سرویس بک‌اند، **Variables** رو باز کنید و این‌ها رو اضافه کنید:
   - `SECRET_KEY` = یک رشته تصادفی طولانی (مثلا با `python -c "import secrets; print(secrets.token_urlsafe(50))"` بسازید)
   - `DEBUG` = `False`
   - `DJANGO_SETTINGS_MODULE` = `config.settings.production`
   - `ALLOWED_HOSTS` = دامنه‌ای که Railway بهتون می‌ده (مثلا `your-backend.up.railway.app`) — بعد از اولین دیپلوی از تب Settings → Networking پیدا می‌کنید
   - `CORS_ALLOWED_ORIGINS` = آدرس سایت Netlify (مثلا `https://your-site.netlify.app`) — بعد از دیپلوی فرانت‌اند این رو کامل می‌کنید
7. Railway خودش از `Procfile` (که توی `backend/` هست) دستور اجرا رو تشخیص می‌ده:
   - `release`: migration و collectstatic
   - `web`: اجرای Django با gunicorn
   - می‌تونید به صورت جدا دو سرویس دیگه هم از همین ریپو (همون root directory `backend`) بسازید و Start Command‌شون رو دستی روی `celery -A config worker -l info` و `celery -A config beat -l info --scheduler django_celery_beat.schedulers:DatabaseScheduler` بذارید (برای یادآورهای خودکار).
8. روی Settings → Networking، **Generate Domain** بزنید تا یک آدرس عمومی (`https://xxx.up.railway.app`) بگیرید. این آدرس رو یادداشت کنید — در مرحله بعد لازمش دارید.
9. بعد از دیپلوی موفق، برای ساخت ادمین اولیه: Railway → سرویس بک‌اند → تب **Shell** رو باز کنید و بزنید:
   ```
   python manage.py createsuperuser
   ```

## بخش ۲: فرانت‌اند روی Netlify

1. به [netlify.com](https://www.netlify.com) برید و با گیت‌هاب وارد بشید.
2. **Add new site → Import an existing project** رو بزنید و همون ریپو رو انتخاب کنید.
3. تنظیمات build (اگه `netlify.toml` رو خودش تشخیص نداد، دستی بذارید):
   - Base directory: `frontend`
   - Build command: `npm run build`
   - Publish directory: `frontend/dist`
   (این‌ها از قبل توی فایل `netlify.toml` توی ریشه پروژه تعریف شدن، پس معمولا خودکار تشخیص داده می‌شه.)
4. قبل از Deploy، توی بخش **Environment variables** این رو اضافه کنید:
   - `VITE_API_URL` = `https://your-backend.up.railway.app/api` (همون دامنه Railway از بخش قبل، به‌علاوه `/api`)
5. **Deploy site** رو بزنید. بعد از اتمام build، یک آدرس مثل `https://random-name-123.netlify.app` می‌گیرید.
6. برگردید به Railway، متغیر `CORS_ALLOWED_ORIGINS` روی سرویس بک‌اند رو با همین آدرس Netlify کامل کنید و Redeploy کنید تا CORS باز بشه.
7. (اختیاری) از Netlify → Domain settings می‌تونید یک ساب‌دامنه دلخواه یا دامنه شخصی خودتون رو وصل کنید.

## بخش ۳: تست نهایی

1. آدرس Netlify رو باز کنید و صفحه لاگین باید بیاد.
2. با یوزری که در مرحله ۹ بخش ۱ ساختید وارد بشید.
3. اگه خطای CORS یا 401 دیدید، مطمئن بشید `VITE_API_URL` (Netlify) و `CORS_ALLOWED_ORIGINS` / `ALLOWED_HOSTS` (Railway) دقیقاً با آدرس‌های واقعی مطابقت دارن (بدون `/` اضافه در آخر آدرس‌های origin).
4. پنل ادمین Django روی `https://your-backend.up.railway.app/admin/` در دسترسه.

## نکات

- هر بار push به شاخه اصلی گیت‌هاب، هم Netlify و هم Railway به صورت خودکار redeploy می‌کنن.
- هزینه: Railway رایگان نیست (پلن‌های usage-based دارن، معمولا چند دلار در ماه برای این سایز پروژه)؛ Netlify برای فرانت‌اند استاتیک رایگانه.
- تغییراتی که در کد اعمال شد: `frontend/src/api/axios.js` (استفاده از `VITE_API_URL`)، `netlify.toml`، `backend/requirements.txt` (gunicorn, whitenoise, dj-database-url)، `backend/config/settings/base.py` (پشتیبانی از `DATABASE_URL` و `CORS_ALLOWED_ORIGINS`)، `backend/config/settings/production.py` (جدید)، `backend/Procfile` (جدید).
